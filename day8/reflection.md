# Day 8 Reflection

**Most difficult concept and how I overcame it.** The hardest concept for me was concurrency: understanding that two requests can both read "seat available" and both succeed, and that this only goes away when the check and the write are one atomic step. At first, transactions and constraints felt like separate topics. I overcame it by writing out the Alice-and-Bob timeline line by line, then testing it with two terminal sessions against a small database. Seeing the second update match zero rows made the idea concrete. Drawing diagrams of each flow and explaining them aloud to a classmate also exposed gaps in my understanding.

**What I would improve in my capstone.** Based on the feedback I received, my capstone needs better error handling and clearer separation of concerns. Reviewers pointed out that some failures, such as bad input or a failed request, were not handled gracefully, and that some of my code mixed too many responsibilities. I would add input validation, return clear and consistent error messages, and split large functions into smaller, testable ones. I would also write tests for the most important paths, because the design work this week showed me how much correctness depends on edge cases I had not considered.

**What I will learn next.** I want to go deeper into databases and system design: indexing, query performance, caching strategies and how real systems handle high traffic. I also plan to learn automated testing and deployment (CI/CD) so I can build projects that are reliable as well as functional. Finally, I want to practise designing more systems like TicketHub, because working through requirements, estimates and trade-offs taught me to think before I code.
